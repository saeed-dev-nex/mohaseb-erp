# محاسب ERP | Mohaseb ERP

[![CI](https://github.com/saeed-dev-nex/mohaseb-erp/actions/workflows/ci.yml/badge.svg)](https://github.com/saeed-dev-nex/mohaseb-erp/actions/workflows/ci.yml)

نسخهٔ چندکسب‌وکاری و پیشرفتهٔ محاسب‌پرو برای شغل‌های مختلف: یک هستهٔ یکپارچه با
**قالب شغلی** (خدمات و تعمیرات، فروشگاه، بازرگانی و پخش، تولیدی، رستوران، خدمات
عمومی) و نقشهٔ راه ماژول‌های حسابداری، انبارداری، فروش و خرید، منابع انسانی،
حقوق و دستمزد و مالیات (حقیقی و حقوقی).

**وضعیت: فازهای ۰ تا ۵ کامل و منتشر شده‌اند** — اسکلت چندکسب‌وکاری
(«کسب‌وکار»، «سال مالی»، عضویت و نقش کاربران، ۱۲ قالب شغلی)، حسابداری
دوطرفه، انبار و خرید، حقوق و دستمزد، مالیات و دارایی ثابت، و مهاجرت
از محاسب‌پرو. در اولین اجرا، «ویزارد راه‌اندازی» در مرورگر باز می‌شود:
ابتدا پایگاه داده انتخاب می‌شود (SQLite یا PostgreSQL) و سپس حساب مدیر
ساخته می‌شود؛ هیچ حساب پیش‌فرضی به‌صورت خودکار ساخته نمی‌شود. بیس این
مخزن محاسب‌پرو است و مستندات پایهٔ آن در ادامه آمده.

## امکانات

### صدور فاکتور
- **فاکتور سریع مرحله‌ای** — صدور در چهار مرحلهٔ کوتاه (مشتری و خودرو ← خدمات ← کارمزد ← وضعیت و ثبت)، کاملاً قابل انجام با صفحه‌کلید
- **پیشنهاد پلاک** — با واردکردن پلاک کامل، آخرین فاکتور همان خودرو پیشنهاد و با یک کلیک مشخصات و ردیف‌هایش بارگذاری می‌شود
- **پکیج‌های خدمات آماده** — تعریف پکیج در تنظیمات و افزودن همهٔ خدماتش با یک کلیک
- **صدور مشابه**، پیش‌نویس خودکار، و پیش‌فرض‌های به‌یادماندنی اپراتور (وضعیت و کارت پرداخت)
- فرم کامل فاکتور با بخش ساخت‌یافتهٔ خودرو/موتورسیکلت (پلاک، شاسی، نوع، مدل، سال)، برگ سبز و سررسید
- **چاپ دقیق یک‌صفحه‌ای** در اندازه‌های A4 و A5 و A6 و خروجی PDF/JPG از برگ فاکتور

### مدیریت و گزارش
- مشتریان، خدمات، هزینه‌ها، چک‌ها، کارکنان و کاربران با **سطوح دسترسی ماژولی**
- گزارش‌های مالی با خروجی Excel و CSV و سابقهٔ تغییرات (Audit)
- گفت‌وگوی زندهٔ کاربران با پیوست فایل و اعلان پیام جدید
- افزونهٔ صدور سریع فاکتور برای Chrome و Firefox

### پشتیبان‌گیری و امنیت
- پشتیبان‌گیری محلی زمان‌بندی‌شده + **پشتیبان ابری رمزنگاری‌شده** روی فضای S3 (مانند آروان‌کلاد) با بررسی checksum و حذف خودکار نسخه‌های قدیمی
- کلیدهای ابری به‌صورت رمزنگاری‌شده در پایگاه‌داده نگهداری می‌شوند، نه متن ساده
- احراز هویت JWT، محدودسازی نرخ تلاش‌های ورود و ثبت رویدادهای حساس

### تجربهٔ کاربری
- تم تیره و روشن با کنتراست بررسی‌شده (استاندارد WCAG AA)
- میانبرهای صفحه‌کلید قابل ویرایش از تنظیمات
- رابط کاملاً فارسی و راست‌چین با تاریخ شمسی و ارقام فارسی، قابل نصب به‌صورت PWA

## راه‌اندازی در Windows

1. مخزن را دریافت کنید:

   ```powershell
   git clone https://github.com/saeed-dev-nex/mohaseb-erp.git
   cd mohaseb-erp
   ```

2. فایل `run.bat` را اجرا کنید و حالت `dev` را انتخاب کنید. اسکریپت محیط مجازی Python و وابستگی‌های backend را آماده می‌کند؛ وابستگی‌های frontend را نیز در اولین اجرا با npm نصب کنید:

   ```powershell
   cd frontend
   npm install
   cd ..
   .\run.bat
   ```

3. برنامه را در نشانی `http://localhost:5173` باز کنید. API در `http://localhost:8000/api/` در دسترس است.

در نخستین اجرا، برنامه به‌جای صفحهٔ ورود، «ویزارد راه‌اندازی» را نشان می‌دهد: گام اول انتخاب پایگاه داده است (ادامه با SQLite پیش‌فرض، اتصال به یک دیتابیس PostgreSQL آماده، یا **ساخت خودکار دیتابیس و کاربر PostgreSQL در همان ویزارد** — فقط با رمز مدیر سرور، بدون نیاز به pgAdmin) و گام دوم ساخت حساب مدیر. در حالت ساخت خودکار، رمز مدیر سرور فقط همان یک بار در حافظه استفاده و هرگز ذخیره نمی‌شود؛ برنامه با کاربر اختصاصیِ کم‌دسترسی کار می‌کند که رمزش خودکار ساخته و رمزنگاری‌شده نگه داشته می‌شود. تا وقتی این ویزارد کامل نشود هیچ حسابی ساخته نمی‌شود؛ پس از آن ویزارد برای همیشه بسته می‌شود.

**ثبت‌نام مشتری با کد مجوز:** ثبت‌نام آزاد وجود ندارد. مدیر از «تنظیمات ← کدهای ثبت‌نام» کد یکبارمصرف می‌سازد و به مشتری می‌دهد؛ مشتری در صفحهٔ «ثبت‌نام» با آن کد حساب می‌سازد، ایمیلش را با کد تأیید فعال می‌کند و بعد از ورود، اولین کسب‌وکارش را خودش روی قالب صنفی راه می‌اندازد. کدهای ایمیلی (تأیید ایمیل، بازیابی رمز، ورود سریع) با SMTP ارسال می‌شوند؛ کافی است متغیرهای محیطی `EMAIL_HOST` و `EMAIL_PORT` و `EMAIL_HOST_USER` و `EMAIL_HOST_PASSWORD` و `EMAIL_FROM` تنظیم شوند (نمونه در `.env.example`). بدون SMTP، کدها روی لاگ سرور چاپ می‌شوند.

برای اجرای production روی یک پورت واحد، از `run_production.bat` و برای دسترسی سایر سیستم‌های شبکهٔ محلی، از `run_network.bat` استفاده کنید.

### نصب به‌صورت اپلیکیشن (PWA)

پس از اجرای نسخهٔ production با `npm run build` و `npm run preview`، برنامه را یک‌بار از `http://localhost:4173` در Chrome یا Edge باز کنید و دکمهٔ «نصب محاسب پرو» را انتخاب کنید (یا از آیکون نصب در نوار آدرس استفاده کنید). سپس برنامه از منوی Start یا میانبر دسکتاپ، بدون وارد کردن آدرس، اجرا می‌شود. نصب PWA به `localhost` یا HTTPS نیاز دارد؛ مرورگرها آن را روی نشانی HTTP شبکهٔ محلی نصب نمی‌کنند.

### به‌روزرسانی در هر سیستم

به‌روزرسانی از داخل خود برنامه تأیید می‌شود: مدیر از بخش «تنظیمات ← به‌روزرسانی» نسخهٔ تازه را می‌بیند و با تأیید او، به‌روزرسانی در اجرای بعدی اعمال می‌شود. اجرای دستی `update_project.ps1` بدون آن تأیید، هیچ تغییری اعمال نمی‌کند و فقط اطلاع می‌دهد که به‌روزرسانی تأییدشده‌ای در انتظار نیست. اسکریپت پیش از هر کاری تغییرات ثبت‌نشدهٔ محلی را بررسی می‌کند و اگر وجود داشته باشند متوقف می‌شود. راه‌اندازها (`run.bat` و `run_network.bat`) هنگام شروع، هیچ به‌روزرسانی‌ای را خودکار دریافت نمی‌کنند.

## اجرا با Docker (همهٔ سیستم‌عامل‌ها)

اگر Docker دارید، بدون نصب Python و Node برنامه کامل بالا می‌آید:

```bash
cp .env.example .env   # سپس در .env یک DJANGO_SECRET_KEY تصادفی بگذارید
docker compose up --build
```

برنامه در `http://localhost:8080` باز می‌شود و API هم مستقیم در `http://localhost:8000/api/` در دسترس است. در اولین باز شدن، ویزارد راه‌اندازی نمایش داده می‌شود تا پایگاه داده را انتخاب و حساب مدیر را بسازید. دیتابیس و فایل‌های آپلودی در والیوم `mohaseb_data` می‌مانند و با خاموش/روشن‌کردن کانتینرها پاک نمی‌شوند.

### اجرای دستی

Backend:

```powershell
cd backend
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
$env:AUTOBAHN_USE_NVX = "0" # برای Python 3.15 در Windows
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Frontend، در ترمینال جداگانه:

```powershell
cd frontend
npm install
npm run dev
```

## پیکربندی

تنظیمات Django را با متغیرهای محیطی انجام دهید؛ نمونهٔ همهٔ متغیرها در فایل [`.env.example`](.env.example) آمده است. برای محیط واقعی، `DJANGO_SECRET_KEY` را به یک مقدار تصادفی و خصوصی تغییر دهید، `DJANGO_DEBUG` را خاموش کنید و دامنه‌های مورداعتماد را صریحاً تعیین کنید. اگر `DJANGO_SECRET_KEY` تنظیم نشده باشد، در اولین اجرا یک کلید تصادفی ساخته و در فایل `backend/.secret_key` ذخیره می‌شود تا با ری‌استارت عوض نشود (توکن‌های ورود و رمزهای ذخیره‌شده معتبر بمانند)؛ تغییر دستی کلید، رمزهای ذخیره‌شدهٔ قبلی را ناخوانا می‌کند. **نکتهٔ مهم برای پشتیبان ابری:** اعتبارنامه‌های ابری با کلیدی مشتق از همین `SECRET_KEY` رمز می‌شوند؛ پس یک نسخه از مقدار `DJANGO_SECRET_KEY` (یا فایل `backend/.secret_key`) را جدا از سرور، کنار پشتیبان‌ها نگه دارید — بدون آن، فایل‌های پشتیبان رمزنگاری‌شده حتی روی سرور تازه هم قابل بازیابی نیستند.

نکتهٔ مهم دربارهٔ متغیرهای محیطی: این برنامه فایل `.env` را نمی‌خواند؛ متغیر باید در همان پنجره‌ای تنظیم شده باشد که راه‌انداز از آن اجرا می‌شود. در PowerShell:

```powershell
$env:DATABASE_URL = "postgres://..."   # تنظیم برای همین پنجره
Remove-Item Env:DATABASE_URL           # حذف از همین پنجره
```

و در cmd: `set DATABASE_URL=...`. متغیرهای سطح کاربر/سیستم (مثل `DATABASE_URL`ای که برای برنامهٔ دیگری مثل محاسب‌پرو به‌صورت دائمی تنظیم شده) ذاتاً روی هر برنامه‌ای اثر می‌گذارند و از تنظیمات داخلی هم بالاترند؛ برای همین، **راه‌اندازهای ویندوز** (`run.bat`، `run_network.bat`، `run_production.bat` و اسکریپت‌های بک‌اند زیر آن‌ها) در شروعِ هر اجرا، `DATABASE_URL` و `REDIS_URL` به‌ارث‌رسیده را فقط برای همان اجرا خالی می‌کنند تا این نصب همیشه پایگاه داده‌اش را خودش انتخاب کند (ویزارد راه‌اندازی / فایل `backend/.db_config.json`) و ویزارد قفل نشود یا مهاجرت‌ها روی دیتابیس برنامهٔ دیگری ننشینند. متغیر سراسری سیستم با این کار دست نمی‌خورد و برنامه‌های دیگر مثل قبل از آن استفاده می‌کنند. مسیر متغیر محیطی همچنان برای اجرای مستقیم بک‌اند (بدون راه‌انداز) و داکر برقرار است. در هر اجرا، خط `Database: … (source: …)` در لاگ backend نشان می‌دهد برنامه واقعاً به کدام پایگاه داده و از چه منبعی وصل شده است.

| متغیر | پیش‌فرض توسعه | توضیح |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | کلید پایدار در `backend/.secret_key` | کلید خصوصی Django؛ در اولین اجرا ساخته و ذخیره می‌شود. برای محیط واقعی صریحاً تنظیم کنید. |
| `DJANGO_DEBUG` | `true` | برای محیط واقعی روی `false` بگذارید. |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | نام میزبان‌های مجاز، جداشده با ویرگول. |
| `DJANGO_CORS_ALLOWED_ORIGINS` | آدرس‌های loopback روی 5173 و 4173 | مبدأهای مجاز frontend، جداشده با ویرگول. |
| `VITE_API_URL` | نشانی backend بر اساس میزبان فعلی مرورگر | نشانی پایهٔ API برای frontend؛ `/api/` را نیز اضافه کنید. |

پایگاه‌دادهٔ SQLite و فایل‌های بارگذاری‌شده در پوشهٔ `backend/` نگهداری می‌شوند و بخشی از مخزن نیستند. از آن‌ها جداگانه پشتیبان بگیرید.

## افزونه‌های مرورگر

- **Chrome:** از صفحهٔ افزونه‌ها حالت Developer mode را فعال و `chrome-extension/` را بارگذاری کنید.
- **Firefox:** برای آزمایش موقت، `about:debugging` → `This Firefox` → `Load Temporary Add-on` را باز کنید و `firefox-extension/manifest.json` را انتخاب کنید؛ نصب موقت با بستن Firefox پاک می‌شود. برای نصب پایدار، بسته را با `firefox-extension/package.ps1` بسازید و پس از دریافت امضای AMO، فایل XPI را نصب کنید. راهنمای تصویری مرحله‌به‌مرحله در [`firefox-extension/INSTALL_FIREFOX_FA.md`](firefox-extension/INSTALL_FIREFOX_FA.md) است.

افزونه‌ها به backend محلی در `http://localhost:8000` متصل می‌شوند.

## ساختار مخزن

```text
backend/           Django REST API، مدل‌ها و مهاجرت‌های پایگاه‌داده
frontend/          برنامهٔ React و ابزارهای Vite
chrome-extension/  افزونهٔ Chrome
firefox-extension/ افزونهٔ Firefox
docs/images/       تصاویر مستندات از محیط واقعی برنامه
frontend/public/fonts/  قلم وزیرمتن (Self-hosted؛ بدون وابستگی به Google Fonts)
run.bat            راه‌انداز تعاملی Windows
run_network.bat    اجرای برنامه در شبکهٔ محلی
run_production.bat اجرای production تک‌پورت در Windows
```

## امنیت و داده‌های خصوصی

پایگاه‌داده، اسناد مشتریان، رسانه‌های بارگذاری‌شده، محیط‌های مجازی و خروجی‌های ساخت در `.gitignore` هستند. پیش از انتشار تغییرات، مطمئن شوید اطلاعات واقعی مشتری یا پشتیبان پایگاه‌داده به مخزن اضافه نشده باشد. حالت شبکهٔ محلی را فقط در شبکه‌ای اجرا کنید که به آن اعتماد دارید. جزئیات بیشتر در [SECURITY](SECURITY.md).

## مشارکت

برای تغییرات بزرگ، ابتدا یک Issue بسازید تا دربارهٔ راهکار هماهنگ شویم. تغییرات را در شاخه‌ای جداگانه انجام دهید و Pull Request را با شرح تغییر و مراحل بازبینی ارسال کنید. راهنمای کامل در [CONTRIBUTING](CONTRIBUTING.md).
